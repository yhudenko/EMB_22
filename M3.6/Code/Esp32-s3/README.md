# Демо KY-040 для ESP32-S3

Приклади для ESP32-S3:

- **program1** — програмне опитування через `RotaryEncoder`:
  [src/program1/main.cpp](src/program1/main.cpp).
- **program2** — апаратний квадратурний підрахунок через PCNT:
  [src/program2/main.cpp](src/program2/main.cpp).
- **program3** — мелодія на пасивному зумері через LEDC PWM без DAC:
  [src/program3/main.cpp](src/program3/main.cpp).
- **program4** — та сама мелодія без `delay()`, автомат станів на `millis()`:
  [src/program4/main.cpp](src/program4/main.cpp).

## Підключення

Підключати модуль при вимкненому живленні плати.

| Контакт KY-040 | ESP32-S3 |
| --- | --- |
| `+` / `VCC` | **3V3** |
| `GND` | GND |
| `CLK` | GPIO4 |
| `DT` | GPIO5 |
| `SW` | GPIO6 |

**Не підключати живлення KY-040 до 5 В:** підтягувальні резистори модуля
можуть подати 5 В на GPIO ESP32-S3, які не є 5-вольт толерантними.
У прикладі також використовуються внутрішні підтягування `INPUT_PULLUP`.
Номери GPIO можна змінити в константах `PIN_CLK`, `PIN_DT`, `PIN_SW`.

## Запуск program1

1. У PlatformIO вибрати середовище **program1** (вже задане за замовчуванням).
2. Виконати **Build**, потім **Upload**. Бібліотеки `RotaryEncoder` та `Bounce2`
   встановляться автоматично через [platformio.ini](platformio.ini).
3. Відкрити **Serial Monitor**, швидкість **115200 бод**. Щоб повторно побачити
   стартове повідомлення, натиснути RESET на платі після відкриття монітора.
4. Обертати ручку: у моніторі з'являються напрямок `CW (+)` / `CCW (-)`
   і поточна позиція. Натискання ручки скидає позицію до нуля;
   утримання не створює повторних натискань.

Якщо напрямок протилежний бажаному, поміняти місцями `CLK` і `DT`
або значення `PIN_CLK` і `PIN_DT` у коді.

## Як це працює

- `CLK` і `DT` — два цифрові сигнали, зсунуті за фазою. Порядок зміни
  їхніх рівнів визначає напрямок обертання; це не аналоговий потенціометр.
- `encoder.tick()` читає сигнали на кожній ітерації `loop()`.
  Бібліотека декодує квадратурні переходи, відсіюючи типове брязкання
  контактів. `getPosition()` повертає кількість кроків.
- `LatchMode::FOUR3` рахує один крок за чотири переходи, із фіксацією
  при `CLK = HIGH`, `DT = HIGH`, як у типового KY-040. Для варіанта з
  фіксацією в обох станах (`00` і `11`), якщо крок з'являється лише через
  один механічний клац, можна спробувати `LatchMode::TWO03`.
- `button.update()` опитує кнопку з антибрязкотом 20 мс.
  `button.pressed()` спрацьовує лише один раз при підтвердженому натисканні.
- Приклад не створює задач FreeRTOS, не використовує його API,
  переривання чи `delay()`: вся логіка знаходиться в `setup()` / `loop()`.
  Сам Arduino framework для ESP32 внутрішньо працює поверх FreeRTOS.

Не додавати довгих блокувальних операцій у `loop()`: під час швидкого
обертання опитування може пропускати переходи. Це навчальний приклад
для ручного обертання, а не високошвидкісний лічильник.

## Запуск program2: апаратний PCNT

Підключення те саме: `CLK` → GPIO4, `DT` → GPIO5, `SW` → GPIO6,
живлення модуля — **3V3**.

1. У **PlatformIO → Project Tasks → program2** виконати **Build**, потім
   **Upload**. `program1` залишається середовищем за замовчуванням.
2. Відкрити **Monitor** для `program2`, швидкість **115200 бод**.
   Натиснути RESET на платі, якщо стартові повідомлення не відобразилися.
3. Обертати енкодер: консоль показуватиме, наприклад,
   `CW (+) | PCNT = 4 | Steps = 1` або `CCW (-) | PCNT = -4 | Steps = -1`.
4. Натискання `SW` скидає апаратний лічильник до нуля.

### Як працює PCNT у цьому прикладі

- Використовується вбудований драйвер ESP-IDF `driver/pcnt.h`, сумісний
  з Arduino-ESP32 2.0.17 у поточній платформі. `RotaryEncoder` не потрібна;
  бібліотека `Bounce2` обробляє лише кнопку, з антибрязкотом 20 мс.
- Два канали `PCNT_UNIT_0` працюють зі спільним лічильником: перший рахує
  обидва фронти `CLK`, використовуючи `DT` для визначення напрямку;
  другий — обидва фронти `DT`, використовуючи `CLK`.
- Це режим **x4**: повний квадратурний цикл дає `+4` або `-4`.
  `PCNT` у консолі — сире значення; `Steps` — `PCNT / COUNTS_PER_STEP`
  з цілим діленням. За замовчуванням `COUNTS_PER_STEP = 4`; якщо енкодер
  має два клацання за цикл, можна встановити `2`. Це лише масштабування,
  а не фіксація стану `FOUR3`, як у `program1`.
- `loop()` лише читає готовий лічильник раз на 50 мс і друкує зміни.
  Апаратний підрахунок відбувається незалежно від цих читань, без `tick()`
  і без користувацького обробника переривань. Консоль показує підсумкову
  зміну за інтервал, а не кожен фронт; знак `CW`/`CCW` залежить від
  підключення енкодера. Для зміни напрямку поміняти `PIN_CLK` і `PIN_DT`.
- Апаратний фільтр відкидає імпульси коротші приблизно за **12,8 мкс**
  (1023 такти APB при 80 МГц). Він **не усуває весь механічний брязкіт**:
  для надійної роботи KY-040 можуть знадобитися зовнішні RC-фільтри
  або додаткова обробка сигналів.
- Це простий приклад без розширення розрядності лічильника: після
  досягнення **+30000 або -30000** PCNT апаратно скидається до нуля,
  тому накопичена позиція втрачається, а індикація напрямку в момент
  скидання не є достовірною. Для тривалого неперервного підрахунку
  потрібне накопичення переповнень через події/переривання PCNT.

## Запуск program3: мелодія без DAC

ESP32-S3 не має вбудованого DAC. LEDC апаратно генерує прямокутний
сигнал потрібної частоти; синусоїдна таблиця та переривання не потрібні.
Мелодія та сама, але тембр відрізняється від синусоїди.

Підключення малого пасивного п'єзозумера при вимкненому живленні:

- GPIO7 → послідовний резистор 100–330 Ом → «+» зумера.
- «−» зумера → GND.

Потрібен **пасивний** зумер без вбудованого генератора, придатний для
керування сигналом 3,3 В. Активний зумер не відтворюватиме ноти як треба.
Звичайний динамік 4/8 Ом або потужний/електромагнітний зумер не можна
підключати безпосередньо до GPIO — потрібен відповідний підсилювач або
транзисторний драйвер. Для триконтактного модуля слід перевірити його
схему, живлення та сумісність сигнального входу з 3,3 В.

У **PlatformIO → Project Tasks → program3** виконати **Build**, потім
**Upload**. Середовище за замовчуванням залишається `program1`.
Вихід можна змінити константою `BUZZER_PIN`. Код використовує LEDC API
Arduino-ESP32 2.x поточної платформи; у версії 3.x цей API змінився.

## Запуск program4: неблокувальна мелодія

Підключення таке саме, як у **program3**: пасивний зумер на GPIO7.
У **PlatformIO → Project Tasks → program4** виконати **Build**, потім
**Upload**. Середовище за замовчуванням залишається `program1`.

`updateMelody()` перевіряє час через `millis()` і перемикає стани:
початок ноти → звучання → пауза 50 мс → наступна нота.
Після мелодії витримується додаткова пауза 2 секунди без блокування.
LEDC генерує звук апаратно, тому після `updateMelody()` у `loop()` можна
виконувати інші короткі дії без `delay()` та тривалого очікування.
Додаткові задачі FreeRTOS не створюються; Arduino-ESP32 використовує
FreeRTOS усередині.
